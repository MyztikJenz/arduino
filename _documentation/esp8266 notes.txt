### Instructions for flashing to AT firmware
** NOTE: The Arduino IDE can't be running at the same time as a firmware update, the port will be busy to esptool

1) Setup programmer board as found here: 
    https://www.allaboutcircuits.com/projects/flashing-the-ESP-01-firmware-to-SDK-v2.0.0-is-easier-now/
    
except don't wire GPIO 0 high. It needs to be held to ground throughout the process.

use the FTDI programmer for this, not an Arduino. Too much a pain in the ass to use a board. ** Remember to ground the FTDI to
    the same ground as the ESP, weird shit ensures if you don't **

2) To put into firmware update mode, GPIO 0 needs held to ground through the entire process. esptool will hang if you dont.
    a) power everything off
    b) wire GPIO 0 to ground
    c) hold RST to ground
    d) power everything on
    e) let go of RST

3) Run "updater.sh"

4) Once done, wire GPIO to high or let it float. Start up Arduino IDE and monitor, power-cycle ESP8266.

if all went well, AT+GMR should show the "good" firmware noted below.

• at vs at_sdio
# https://github.com/espressif/ESP8266_NONOS_SDK/issues/9
"at" uses UART to send AT commands.
"at_sdio" uses SDIO.

• BOOT vs NON-BOOT
# https://bbs.espressif.com/viewtopic.php?t=1137
boot mode : After connected to AP, ESP8266 can upgrade the AT firmware through WiFi by command 
"AT+CIUPDATE". This mode need the flash size to be 1MBytes or larger than that.

non-boot mode : ESP8266 can not upgrade the AT firmware through WiFi. The flash size can be 512KB.

• cu vs tty
# https://stackoverflow.com/questions/8632586/macos-whats-the-difference-between-dev-tty-and-dev-cu
tty is an incoming traffic port that blocks when open() is called on it. cu is the outbound traffic 
port that can be used even if the tty port is blocked.
